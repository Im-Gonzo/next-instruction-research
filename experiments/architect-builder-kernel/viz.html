Does the kernel stay exact when prose breaks?

Two experiments comparing how an architect describes a 2D block tower to a builder: in natural language versus a shared kernel of named shapes. Tokens via tiktoken o200k_base. The key finding: on an irregular tower, natural language broke (IoU 0.862, missed + invented cells); the kernel stayed exact.

03 / AMORTIZATION — CUMULATIVE TOKEN COST

The kernel definition costs 216 tokens once. After that, each tower description is ~22 tokens vs ~194.5 for natural language. Break-even at 1.25 towers.

Per tower the message shrinks ~9x (194.5 -> 22 tokens). By 20 towers the kernel is 5.9x cheaper. Both builders reconstructed every tower exactly — the compression was lossless.

04 / REGULARITY LADDER — TOKENS vs FIDELITY

As towers get less compressible, the kernel's token advantage narrows (8.2x -> 1.8x). But the kernel stayed exact at every level while concise NL prose broke on the irregular tower.
