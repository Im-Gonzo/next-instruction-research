The interface is the next instruction.

An operator and an AI invent shared shorthand over repeated trials. That shorthand — not prose — is the right primitive for handing work to an agent.

Three experiments measured it: token cost, structural fidelity under compression, and a live architecture reconstruction. The finding holds at every level.

01 / 11 — the premise

Most UI assumes a human is reading.

When the consumer of your interface is an agent, the screen is not an output to look at — it is the input the model acts on. What you hand the agent determines every next step.

So the honest question becomes: what is the smallest, most reliable way to hand an agent a complex structure? We kept reaching for the wrong noun to describe what we were building.

framework
tempting: it ships reusable substrate.but there is nothing to build against — you mount your work on it and it watches.
experiment
tempting: it is the running test of a published finding.but it never stops to conclude — the experiment and the workbench are the same surface.
agent
tempting: agents run inside it.but the agents are tenants, not the thing — the thing dispatches them.
architecture
tempting: it has a layered structure.but architecture is the static noun; this one changes shape as you type intent.

The real primitive is context — and the question is how to make it dense, exact, and cheap.

02 / 11 — scope to ideas

Scope the work to an idea, not a directory.

The idea-harness: a path resolves to the idea that owns it. The session inherits that idea's context on resume. Leaving the idea's boundary is an EXCURSION — surfaced inline, not silently mis-attributed.

A repo-scoped session leaks everything in: unrelated workstreams, stale context, half-complete ideas competing for the model's attention. The cwd/repo binding silently mis-attributes work and corrupts the compression the kernel depends on.

The excursion prompt — "write plan-b/…? outside this idea — allow / re-bind / split" — keeps the context boundary sharp without demanding discipline from the operator.

03 / 11 — reference + method

Fan's architect/builder, run on a human–AI dyad.

In Fan's block-tower studies, two players have asymmetric roles: an architect who sees the target and describes it; a builder who can only act on words. Over repeated trials the language compresses into shared names. Wong et al. 2022 established the qualitative tradeoff — too few names forces re-derivation, too many produces retrieval noise. Our operating window of 25–60 primitives is where we found the cost curve bottoms out in practice.

Our dyad: operator = architect, Claude session = builder, the substrate = a lexicographer that watches every channel and proposes convergent names. Built and run in a week with Claude Code — agents played every role including building these visuals.

04 / 11 — experiment 1 · context cost

A name is paid for once, invoked forever.

Named primitives are the compression layer. Experiment 1 measured it: the same 2D block tower described two ways — natural language vs. a shared kernel of named shapes.

The kernel costs ~9x fewer tokens per object — measured against the fully-explicit prose below, and amortized over reuse: its 216-token definition is repaid by the 2nd object (break-even ≈ 1.25), but for a true one-off, plain language is cheaper. Both reconstructions were exact — the compression is lossless.

what stack(C,Pi,L) means — and the prose it replaces

05 / 11 — experiment 2 · brief AND exact single run · failure-rate unmeasured

Prose broke. The kernel didn't.

Push toward irregular structures and the token lead shrinks (8.2x at L1, 1.8x at L3) — incompressible structure forces the kernel back to individual block primitives. In this run, concise prose got it wrong while the symbolic kernel stayed exact.

The failure was encoder-side: the architect's prose was wrong before the builder read it. "col 2 is solid r0–r3" — column 2 fills r0, r2–r5. Builder faithfully added (2,1), dropped (2,4). IoU 0.86.

The durable edge is not brevity: a name can't be vague — and, unlike prose, it can be checked. One worked case, not yet a measured rate.

07 / 11 — two rules keep it compressible

Two rules keep it compressible.

PIGEONHOLE — load is the ratio of primitives vs. sibling workstreams, not raw count. When a bucket strains (too many primitives for one idea), split it. The library-size U-curve made operational: you do not optimize globally, you re-cleave locally.

PARETO — most agent questions are not scalar. Brevity alone is not enough; exactness alone is too expensive. The kernel is brief AND exact, so it dominates prose on both axes simultaneously. No prose register reaches the non-dominated corner.

The scatter is real Experiment-3 data: each point is a builder's median edge-F1 (10 Haiku runs, min–max whiskers) against the tokens to encode the architecture. The kernel sits alone in the non-dominated corner — fewer tokens and higher fidelity than both a concise human summary and the raw transcript.

08 / 11 — the larger hypothesis

Layered named context.

One framework, three levels. L1 ideas are the context unit — what is inherited when a session opens. L2 workstreams have capacity (pigeonhole: split when a bucket strains). L3 primitives are the kernel — measured, lossless, cheap.

Selection across layers is multi-objective (Pareto): you want fewer tokens and higher fidelity, simultaneously. The kernel sits on that frontier.

Honest frontier: the experiments prove L3 directly. Idea-scoping (L1), pigeonhole (L2), and the Pareto framing are the hypothesis — consistent with the data but not yet separately measured. That is the next round.

09 / 11 — the operator surface

From prose to a named handoff.

If the interface is the next instruction, the operator shouldn't re-type structure as prose every session. The surface should notice repeated structure, propose a name, and let you hand an agent a primitive instead of a paragraph — with a guard when work strays outside it.

scope & caveats
  • Small n, authored stimuli. Exp 1–2 use toy towers the kernel itself authored — so lossless reconstruction is partly true by construction. Exp 3 (a real talk the kernel did not author) is the unrigged test — 30 builder runs against a validated graph.
  • Small samples. Token counts are deterministic (tiktoken). Exp 1–2 fidelity came from single, non-deterministic agent runs (a worked case); Exp 3 is 30 runs/condition — a measured failure rate (kernel 0% · prose 0% · transcript 40%) — but still one architecture, one builder model.
  • Hypothesis vs. proven. The experiments support L3 (the kernel) directly; idea-scoping (L1), pigeonhole (L2), and the Pareto framing are consistent with the data but not yet separately measured. The 25–60 window is our own operating range, not a literature finding.
