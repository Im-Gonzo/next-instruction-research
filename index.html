We kept reaching for the wrong noun.

Is it a framework? An experiment? An agent? An architecture? After a week of building it — and watching it build itself — the closest honest word is instrument: a way of working that records its own formation, built to run a cognitive-science finding on the dyad doing the running.

01 / WHAT IS THIS

Four nouns keep getting reached for. Each is tempting; none quite holds.

framework
tempting: it ships reusable substrate — channels, hooks, panels, MCP.but there's nothing to build against; you mount your work on it and it watches.
experiment
tempting: it's the running test of a published finding.but it never stops to conclude — the experiment and the workbench are the same surface.
agent
tempting: agents run inside it on Anthropic Managed Agents.but the agents are tenants, not the thing — the thing is what dispatches them.
architecture
tempting: it has a layered structure — root → ideas → workstreams → primitives.but architecture is the static noun; this one changes shape as you type intent.

It behaves most like an instrument — a substrate that measures its own way of working.

And the thing it instruments is a result from cognitive science: Judy Fan's architect / builder paradigm. The rest of this note is that result, how we run it, and what it showed.

02 / THE REFERENCE — JUDY FAN'S ARCHITECT & BUILDER

In Fan's block-tower studies, two people play asymmetric roles across repeated trials: an architect who can see the target and must describe it, and a builder who can only act on the description. Over trials the architect's language compresses — natural-language phrases co-emerge with reusable program fragments. A shorthand forms because both partners now share a history.

Scaled up, library induction follows a U-curve over the count of named primitives: too few forces re-derivation every time; too many produces retrieval noise (Wong et al. 2022). Under a tighter communication budget, dyads diverge into distinct local dialects rather than converge across producers. Convention is the residue of repeated reference under a budget.

03 / HOW WE WORK IT

We didn't build Fan's experiment as a study. We are the dyad — and we added a third seat the literature implies but never names.

The operator is the architect; a Claude session is the builder; an append-only ledger is the shared notebook the next session reads on resume — memory the lab dyads never had. Their finches are individual humans under a timer; ours is an operator–model pair iterating against a substrate that enforces the shared history.

the working loop — three seats over one append-only ledger, and the return arc the lab dyads never had

A name is not the residue of a procedure; it is the seat the procedure can return to.

    05 / THE EXPERIMENT — DOES THE KERNEL ACTUALLY COST LESS?

    The open test, run. Same target — a 2D block tower — given to a builder two ways: in natural language, and in the shared kernel of named shapes. We measured the tokens the builder must consume (tiktoken · o200k_base) and checked every reconstruction against ground truth. Architect = Sonnet, builder = Haiku, harness at experiments/architect-builder-kernel/.

    experiment 1 · amortized context cost — cumulative tokens to build N towers; the kernel pays its definition once, then stays near-flat per tower

    Per tower the architect's message shrinks ~9× (≈194 → ≈22 tokens). The 216-token kernel definition is repaid after 1.25 towers; by 20 towers the kernel is 5.9× cheaper. Both builders reconstructed the tower exactly — the compression was lossless.

    experiment 2 · the regularity axis — kernel vs. natural-language tokens as towers get less compressible; ✓/✗ marks whether concise prose survived reconstruction

    Push toward irregularity and the token lead collapses — 8.2× → 1.8× — because incompressible structure forces the kernel back to primitives. But the kernel stayed exact at every level, while concise natural language broke on the irregular tower (the builder missed one cell and invented three). The kernel is the only register that is both brief and exact.

    The naming substrate buys exactness under compression pressure; tokens are just the visible part.

    A shared name is not only shorter — it is the one description that cannot be misread. Full harness, both experiments, and the builder transcripts live at experiments/architect-builder-kernel/.

    06 / THE UNRIGGED TEST — A REAL ARCHITECTURE

    The towers above were authored by the kernel itself — so lossless reconstruction was partly true by construction. The unrigged test takes a real engineering talk (an ex-Atlassian self-service edge platform), rebuilt as a component graph — a validated 39 nodes / 48 edges — and hands it to builders three ways: the raw transcript, a concise human summary, and the kernel. 30 independent Haiku builders (10 per condition) reconstruct it over a shared vocabulary; pre-registered, harness at experiments/architecture-transcript/.

    experiment 3 · real architecture — encoding tokens (log) × reconstruction fidelity (edge-F1); each point is the median of 10 builder runs with min–max whiskers; the kernel sits alone in the non-dominated corner

    The kernel rebuilt the graph at 0.98 edge-F1 with 0 failures, vs. a concise human summary at 0.80 (0 failures) and the raw transcript at 0.56 (40% of runs failed) — complete separation between kernel and prose (every kernel run beat every prose run; Mann–Whitney U = 0, p ≈ 0.0002). Even careful prose loses structure that the symbolic spec keeps.

    Honest: for this single architecture the kernel's total (547 tok, incl. its one-time 389-token definition) is larger than the prose summary (298) — the token win is the amortization story above; here the win is fidelity + reliability. One architecture, one builder model.
